# Release 0.2.0 (2026-10-23)

A rule the team's oxlint config states is the team's even in a line oxlint skips, and our typed blocks ask per file whether a tsconfig takes it in (O5, O7, LD-O5b, LD-O7b, q-lint-o7-cast, q-dogfood-keep-three, status.md rows 14–17)

**Before you upgrade.** Where your oxlint config states a rule of a plugin it lists neither at its root nor in
that override, oxlint skips the line, and our config no longer runs the rule either. To have it reported, list
the plugin.

## Changed

### O5 — a rule the team's oxlint config states is the team's, even in a line oxlint skips

- A line of the team's oxlint config stating a rule makes the rule the team's, at any severity, at a root or in
  an override. That now includes a line oxlint skips because its plugin is listed neither at the root nor in
  that override (owner 2026-10-22, card LD-O5b, reversing the default `spec-owner-answers.md` listed).
- Both our parts drop the rule, and the skipped line stays skipped, so nothing reports the rule until the team
  lists the plugin.
- `merge-oxlint-config.integration.test.ts` runs oxlint on such a line stated `off` and `error`, and
  `editor-merges.team-sets-a-rule.integration.test.ts` runs both engines' CLIs on one.

### O7 — our typed blocks ask, as ESLint lints each file, whether a tsconfig takes it in

- Where the type information is ours, each typed block's `files` ANDs a function with its globs
  (`keptToFilesATsconfigTakesIn`, `build-eslint-config.ts`) in place of a list of literal paths made as the
  config loaded (owner 2026-10-22, card LD-O7b).
- A TS file made after an editor's ESLint loaded the config no longer needs a restart: it is read as the disk
  then holds it (`outside-every-tsconfig.made-later.integration.test.ts`).
- `projectFactsOf` gives `isOutsideEveryTsconfig`, which answers each file once, by its path. `tsconfigWalkOf`
  reads each tsconfig once, and asks a file the walk did not find of the tsconfigs read afresh.
- ESLint documents only globs in `files`, and its types hold no more, so `filesEntryAlsoMatching`
  (`eslint-file-types.ts`) holds one type assertion. The owner allowed it there alone (q-lint-o7-cast), and
  this repo's `agents-inc.lint.mts` turns `@typescript-eslint/no-unsafe-type-assertion` off for that file.
  `eslint-function-in-files.test.ts` fails where a later ESLint stops calling the function.
- **Written limit:** until the editor's ESLint restarts, a TS file keeps the answer it got when first linted,
  so a tsconfig edited later to take it in does not bring it our typed rules (`plan.md` Open).

### status.md rows 14, 16 and 17 — the owner's answers on three code questions

- **Row 14 (q-dogfood-keep-three):** a switch covering every case of a union ends in
  `default: { const unhandled: never = x; return unhandled }`, so a missing case stays a type error and
  `consistent-return` stays quiet. `build-eslint-config.ts`'s three `TypeInformation` checks are such switches.
- **Row 16:** `RuleRoute` (`catalog.ts`) is a union on `engine`, so a route oxlint runs always carries
  `oxlintName` and `oxlintPlugin`. `isOxlintRoute` no longer throws; `parseRuleRoute` refuses a generated
  route that breaks the rule, and `catalog.test-d.ts` pins it for tsc.
- **Row 17:** the test helper `oxlintCodeOfRule` cuts the name with `ruleNameOf`, as production does.

### Tests

- Unit tests for the CLI's folder walk (`foldersUpTo`), package-manager pick (`packageManagerOf`), config
  lookup (`nearestConfig`), command parsing (`commandOf`, `belowTheNodeFloorLine`), and changed lines after
  `git mv` and in a repo with no commit yet (`changedLinesOf`).
- Two gaps Stryker found on the O5 and O7 lines have tests: beside the team's type information, our typed rules
  stay out of the consumer's config files at any depth; and only a consumer file is read as typed through an
  importer.

## Fixed

### status.md row 15 — `house/hook-file-naming` counts `export enum` and `export namespace` as values

- A module exporting a hook beside `export enum Status` or `export namespace Status` was told to rename its
  file for the hook. Both now count as values, as `export class` does. A dotted namespace counts under its
  first name, and a module named by a string binds none.
