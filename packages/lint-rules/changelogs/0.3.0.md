**Before you upgrade.** New rules ship at `error`, so a project that passed `check` on 0.2.0 can fail it. A rule
runs where your config lists its ruleset. Rulesets that gain shipped rules: `correctness` 20, `redundancy` 10, `zod`
9, `playwright` 7, `conventions` 6, `modern-js` 5, `tanstack-query` 5, `browser` 4, `tests` 4, `security` 2, and one
each in `immutability`, `type-safety`, `performance`, `node`, `react` and `tanstack-router`.

- `jest-dom` (7 rules) and `react-ssr` (4) are opt-in now, so `init` no longer lists them; a config `init` wrote at
  0.2.0 lists both and gains those 11 rules.
- `comments` gains 3, run only where suppressions are allowed.
- Opt-in: `browser-targets` gains `compat/compat`, `tailwind` gains `shadcn/no-raw-colors`. The new `effect` ruleset is
  off until listed (`libs: { effect: ['effect'] }`).
- 27 shipped rules change ruleset, two of them to off by default; each runs where its new ruleset is listed.
- Turn one rule off with `rules: { '<rule id>': 'off' }` in `agents-inc.lint.mts`; drop a ruleset by deleting its name
  from `agentRulesets` or `editorRulesets`.
- `rules` and `fileOverrides[].rules` refuse a rule we do not ship, the four removed below included. Turn such a rule on
  in your own ESLint or oxlint config.
- The editor merges refuse a null your oxlint config holds where oxlint refuses one, naming the file and the key.
- `no-unused-vars` now checks `scripts/` and `*.config.*` files.

## Added

### #83 — nine more ESLint plugins, eslint-plugin-drizzle-security left out

- `@e18e/eslint-plugin`, `@eslint-community/eslint-plugin-eslint-comments`, `@shadcn/lint`,
  `@tanstack/eslint-plugin-query`, `@tanstack/eslint-plugin-router`, `eslint-plugin-hydration-proof`,
  `eslint-plugin-jest-dom`, `eslint-plugin-playwright` and `eslint-plugin-zod` are pinned dependencies, registered
  with our plugins.
- `eslint-plugin-drizzle-security` stays out; its two rules are `dropped` in `rule-candidates.json`
  (q-lint-dep-drizzle-advisory).

### owner-2026-10-11 — the rules accepted on the old candidates page ship

- New in `correctness`, `redundancy`, `conventions`, `modern-js`, `browser`, `tests`, `security`, `immutability`,
  `type-safety` and `react`, each placed as the page proposed and then as the round-2 critique moved it (#7).
- `house/no-reduce-accumulator-copy` ships in `performance`: it reports a `reduce` callback that copies its accumulator
  every step.
- `unicorn/prefer-literal-ascii` ships, so `unicorn/no-hex-escape` is removed (r2-d68).
- Each rule not shipped names its card in `rule-candidates.json`.

### 2026-10-24 rule-candidate cards (`rc-…`) — zod, TanStack, Playwright, e18e and core rules

- `zod` gains 9 rules, `tanstack-query` 5, `tanstack-router` `@tanstack/router/route-param-names`, `playwright` 7, `node`
  `e18e/prefer-throw-if-no-entry`.
- `modern-js` gains `prefer-named-capture-group` and `sonarjs/prefer-native-axios-alternative`; `redundancy` gains
  `unicorn/prefer-logical-operator-over-ternary`, and `unicorn/no-repeated-call-wrappers` outside test files.
- `playwright/no-element-handle` and `playwright/no-wait-for-selector` run in test files alone, since they also report
  Puppeteer's `page` (q-lint-rc-pw-puppeteer-page).
- `@tanstack/query/stable-query-client` and `zod/prefer-trim-before-string-length-checks` report and are never
  rewritten (q-lint-rc-stable-query-client-fix-measured, q-lint-rc-zod-trim-fix-measured).
- `tailwind` (opt-in) gains `shadcn/no-raw-colors`.
- Each verdict, and each rule held or dropped, is in `rule-candidates.json` under its card.

### q-lint-jest-dom-without-jest-dom — jest-dom is opt-in and ships seven rules

- `init` no longer lists `jest-dom`. It holds `prefer-checked`, `prefer-empty`, `prefer-in-document`, `prefer-pressed`,
  `prefer-required`, `prefer-to-have-attribute` and `prefer-to-have-class`.
- `check` reports all seven and rewrites none: their fixes break passing tests (q-lint-rc-jest-dom-fixes-measured,
  q-lint-rc-pressed-fix-current-jest-dom).

### q-lint-react-ssr-in-client-apps — react-ssr is opt-in and ships four hydration rules

- `init` no longer lists `react-ssr`. It holds `hydration-proof/no-storage-in-initial-render`,
  `no-timezone-without-explicit-timezone`, `no-window-render-branch` and `require-stable-server-snapshot`
  (q-lint-hp-timezone-hold, q-lint-hp-server-components-gap).
- `no-browser-global-in-render` and `no-locale-without-explicit-locale` stay unshipped
  (q-lint-rc-hydration-false-alarms-measured, q-lint-hp-left-off-record).
- A JS or TS file whose nearest `package.json` lists `next` gets `serverComponents: 'next-app'`, so a page only the
  server renders is not reported (q-lint-hp-next-setting-where).

### q-lint-compat-default-target — compat/compat ships in browser-targets

- `eslint-plugin-compat` is a dependency (q-lint-compat-install-size). `compat/compat` ships in the opt-in
  `browser-targets` with Vite 8's build target as its query: `chrome >= 111, edge >= 111, firefox >= 114, safari >= 16.4,
  ios_saf >= 16.4` (q-lint-compat-vite-target).

### q-lint-effect-ruleset-name — the effect ruleset

- A `libs` domain `effect` holds the ruleset `effect`, which `init` lists. It holds `house/no-manual-effect-error-tag`:
  a hand-written `_tag` check inside Effect's catch-everything handlers, pointing to `catchTag`, `catchTags`,
  `catchReason` or `catchReasons`.

### q-lint-rc-duplicate-disable-measured — three eslint-comments rules ship in comments

- `@eslint-community/eslint-comments/disable-enable-pair`, `no-duplicate-disable` and `require-description` run only
  where suppressions are allowed, like `unicorn/no-abusive-eslint-disable`.
- `require-description` asks a reason after `--` of a switch-off comment, oxlint's spellings included
  (q-lint-cmt-oxlint-disable-reason), and of a comment setting a rule for its file (q-lint-cmt-inline-config-reason).
  Enable comments need none (q-lint-cmt-require-description-scope).

### q-lint-pw-off-by-default-where — a rule can ship off by default

- A rule shipped `offByDefault` is in no ruleset and runs only where `rules` or a `fileOverrides` entry names it. 18 ship
  so.
- The 11 newest-language rules, which ask for APIs Node 22 lacks; nine have their fix withheld
  (q-lint-newest-language-fix).
- `playwright/no-focused-test`, `no-identical-title`, `prefer-hooks-on-top` and `require-to-throw-message`, which repeat
  a `vitest/*` rule (q-lint-playwright-vitest-twins), and `playwright/prefer-web-first-assertions`, which does not work
  in unit tests (q-lint-rc-web-first-assertions-measured).
- `unicorn/prefer-dom-node-html-methods` and `unicorn/prefer-location-assign` leave `browser`, their fixes withheld:
  each broke a jsdom test (q-lint-jsdom-off-rules-fix).

## Changed

### #7 — the round-2 ruleset critique regroups rules

- 23 shipped rules move as the owner's 2026-10-30 cards ruled (owner-2026-10-30): a rule that catches a bug sits in
  `correctness` (q-lint-crit2-bug-checks-in-tidying-groups); `type-safety` holds weaker type checking, and the bans on
  enums, namespaces and parameter properties go to `conventions` (q-lint-crit2-type-safety-scope); `modern-js` holds
  rewrites needing a newer feature (q-lint-crit2-modern-js-scope); `react/no-children-prop` goes to `conventions`
  (q-lint-crit2-no-children-prop); `unicorn/no-late-event-control` and `no-late-current-target-access` go to
  `correctness` (q-lint-crit2-late-event-rules); four single placements (q-lint-crit2-single-placements).
- `@eslint-react/x-no-leaked-conditional-rendering` moves from `react` to `correctness`, under the owner's 2026-10-10
  ruling that `react` keeps what depends on React.
- `@typescript-eslint/prefer-namespace-keyword` runs in ESLint in declaration files alone (q-lint-crit2-namespace-keyword).
- Each rule's `assignment` in `data/rules.json` names the decision and card that placed it.

### q-lint-slice2-autofix — oxlint runs 36 more rules

- 36 shipped rules move from ESLint to oxlint, `unicorn/prefer-modern-dom-apis` among them
  (q-lint-prefer-modern-dom-apis-engine).
- ESLint keeps 13 rules whose fix only ESLint's version makes, and 5 whose oxlint fix changes what the code does
  (q-lint-slice2-oxlint-fix-changes-meaning). Each names its card in `eslintBecause`.

### q-lint-unshipped-rules-channel — a team config names only rules we ship (#4)

- `rules` and `fileOverrides[].rules` refuse any other rule, an unknown ID included, with a message naming the config.
- The other copy of a rule we ship (typescript-eslint's of a core rule, or the reverse) counts as shipped
  (q-lint-unshipped-ts-twin).

### q-lint-oxlint-null-options — nulls in a team's oxlint config

- Both editor merges refuse a null where oxlint 1.87 refuses one, in the team's config and each config it extends, with
  one line naming the file, the path to the null and what to write there (q-lint-oxlint-null-beside-extends,
  q-lint-oxlint-null-other-keys, q-lint-oxlint-null-deeper).
- A null among a rule's options or in a plugin's settings field is left to oxlint
  (q-lint-oxlint-null-rule-options-and-settings).

### q-lint-presence-queries-attribute-fix — check withholds fixes that break jsdom tests

- `check` reports and never rewrites `testing-library/prefer-presence-queries` and unicorn's `dom-node-dataset`,
  `prefer-add-event-listener`, `prefer-keyboard-event-key`, `prefer-modern-dom-apis`, `prefer-query-selector`,
  `prefer-https` and `require-css-escape` (q-lint-jsdom-add-event-listener-fix, q-lint-jsdom-css-escape,
  q-lint-jsdom-dataset-fix, q-lint-jsdom-keyboard-event-key-fix, q-lint-jsdom-modern-dom-apis-fix,
  q-lint-jsdom-query-selector-fix, q-lint-jsdom-src-prefer-https).
- `withheld-fixes.json` lists 38 rules, 32 more than 0.2.0.
- `unicorn/no-useless-spread` runs in ESLint, as oxlint's fix broke a test (q-lint-jsdom-src-no-useless-spread).

### q-lint-jd-editor-fixes — editors withhold the same fixes

- In the editor merges every rule whose fix `check` withholds reports with no fix and no suggestion
  (q-lint-editor-withheld-fix-suggestions). No setting turns them back on (q-lint-editor-withheld-fix-switch).
- Beside oxlint, the ESLint part runs each such oxlint-routed rule ESLint can run, and the oxlint merge turns oxlint's
  copy off.
- A rule a team sets in its own config keeps its plugin's fix and suggestions (q-lint-editor-withheld-fix-team-set) and
  our crash repairs (q-lint-team-set-repaired-copies).

### q-lint-cmt-editor-reach — editors run a rule only where its ruleset is listed

- A rule `allowSuppressions` turns on runs in the editor parts only where `editorRulesets` lists its ruleset.
- `@typescript-eslint/ban-ts-comment` moves into `type-safety`, so editors run it only where that is listed; `check`
  still sets it by `allowSuppressions` (q-lint-ban-ts-comment-editor).

### q-gap-lint-ts-comment-message — the @ts-ignore message where @ts-expect-error is banned too

- Our blocks' `ban-ts-comment` says "remove it and fix the type error it hides" for a `@ts-ignore`, with no swap
  suggestion (q-lint-ts-ignore-quick-fix). Editors and test and setup files keep typescript-eslint's advice
  (q-lint-ts-ignore-message-editor).

### q-gap-lint-a11y-original-prefix — rules a team sets in the editor merges

- A team plugin carrying `eslint-plugin-jsx-a11y`'s name is our jsx-a11y under the team's prefix: one report, at the
  team's setting.
- A plugin a team's oxlint config lists only in overrides counts toward the rules it sets except where oxlint runs that
  plugin's category rules in no file (q-lint-oxlint-override-category-plugins).
- Where one override alone lists typescript, its category rules stay the team's in every file
  (q-lint-oxlint-override-leaves-out-root-plugin).

### q-gap-lint-unused-vars-scripts-config — no-unused-vars checks scripts and config files

- It no longer ignores `**/scripts/**` and `**/*.config.{ts,js,mjs,cjs}`; it still ignores stories.

### q-lint-setup-files-which — setup files count as test files

### q-lint-compat-stale-data-warning — check silences browserslist's old-data message

### q-gap-lint-typescript-eslint-version — typescript-eslint 8.71.2

- `typescript-eslint` and every `@typescript-eslint/*` package a user's install reaches are listed at 8.71.2, so npm

### q-lint-own-published-types — the merges take a read-only theirs

## Fixed

### q-lint-own-gate-per-file — functional/prefer-immutable-types answers each call afresh

- is-immutable-type's cache made the rule answer by what it checked first, so one run missed an overwritable utility
  type. Our plugin registry wraps the rule, so `check` and editors report every one.

### q-lint-immediate-return-using-fix — prefer-immediate-return leaves using alone

- `sonarjs/prefer-immediate-return` neither reports nor rewrites a returned or thrown variable a `using` or
  `await using` declaration holds (q-lint-immediate-return-thrown-using).

### q-lint-barrel-entry-how — no-barrel-files skips src/index

- `unicorn/no-barrel-files` ships with `ignores: ["**/src/index.*"]`.

### q-lint-check-no-config-folder-twice — check names the folder once

- Run at a git top level holding no `agents-inc.lint.mts`, `check` names that folder once.

### check labels oxlint's react-hooks findings as react-hooks/…

- oxlint prints `rules-of-hooks` and `exhaustive-deps` under `react-hooks`; `check` labels them
  `react-hooks/rules-of-hooks` and `react-hooks/exhaustive-deps`.

### check survives a changed file deleted while oxlint runs

- A file gone before oxlint opened it is no oxlint failure: `check` keeps oxlint's other findings and lists that file
  itself.

### `plugins: null` in a team's oxlint config

- Both merges read it as oxlint does, as `plugins` left out, where they threw a `TypeError`.

### Globs cover every JS and TS extension

- Test and setup files ending `.mts`, `.cts`, `.mjs` or `.cjs` get test files' relaxed rules.
- `functional/no-expression-statements` and `functional/no-return-void` check `.mts` and `.cts` files as they do `.ts`.
- Story globs name all eight extensions.
